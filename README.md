# sounds of electronic art — GitHub Pages site

A dependency-light static website for the **sounds of electronic art** radio show.

## Features

- responsive orange design
- German default interface with an English language switch
- dark theme and a Solarized-Light-inspired light theme
- multiple upcoming broadcasts and events
- five featured SoundCloud recordings with an in-page player
- statically generated and searchable broadcast archive
- real, crawlable detail URLs for broadcasts and events
- in-page modal/drawer detail UX on the homepage, with normal navigation as a no-JavaScript fallback
- RSS feed, sitemap, robots.txt and custom 404 page
- separate deployment and scheduled SoundCloud-cache workflows
- no first-party analytics, advertising tracking or externally hosted web fonts

SoundCloud players are third-party embeds and are covered separately in the privacy notice.

## Project structure

```text
assets/                  CSS, JavaScript, icons and images
content/site.json        general site, team and featured-player content
content/episodes.json    upcoming entries and local archive enhancements
content/archive-cache.json
                         generated SoundCloud archive cache
content/legal.json       legal operator details
docs/                    Search Console and structured-data guidance
scripts/build.py         static-site generator
scripts/update_archive.py
                         SoundCloud cache updater
scripts/validate_site.py source/output validation
templates/               page templates
```

Do not edit `public/`; it is regenerated by the build.

## Canonical domain

The canonical site URL is configured in `content/site.json`:

```json
"url": "https://sofea.radio"
```

GitHub Actions supplies the deployed Pages URL through `SITE_URL`. To override it locally:

```cmd
set SITE_URL=http://localhost:8000
py scripts\build.py
```

## Edit general content

General information, team links and featured SoundCloud recordings are maintained in:

```text
content/site.json
```

Only the first five entries in `mixes` are shown in the **Hören / Listen** overview.

## Add upcoming broadcasts and events

Upcoming items are maintained in:

```text
content/episodes.json
```

Every future object with:

```json
"status": "upcoming"
```

is shown in chronological order. Past entries disappear from Upcoming during the next build.

### Broadcast example

```json
{
  "date": "2026-08-29T21:00:00+02:00",
  "end": "2026-08-30T00:00:00+02:00",
  "type": "broadcast",
  "status": "upcoming",
  "title_de": "sofea #100 - tba",
  "title_en": "sofea #100 - tba",
  "summary_de": "Drei Stunden elektronische Musik. Live auf Radio Blau.",
  "summary_en": "Three hours of electronic music. Live on Radio Blau.",
  "audio_url": null
}
```

### Event example

```json
{
  "date": "2026-09-12T20:00:00+02:00",
  "end": "2026-09-13T02:00:00+02:00",
  "type": "event",
  "status": "upcoming",
  "title_de": "sofea night",
  "title_en": "sofea night",
  "summary_de": "Eine Nacht mit dem sofea-Team und Gästen.",
  "summary_en": "A night with the sofea team and guests.",
  "details_de": "Längerer Beschreibungstext für die Detailansicht.",
  "details_en": "Longer description for the detail view.",
  "location_de": "Conne Island, Leipzig",
  "location_en": "Conne Island, Leipzig",
  "image": "assets/images/sofea-night.jpg",
  "lineup": [
    {"name": "96kbps", "url": "https://soundcloud.com/skile"},
    {"name": "easy.miner", "url": "https://soundcloud.com/easy_miner"},
    {"name": "fumé", "url": "https://soundcloud.com/fume"}
  ],
  "links": [
    {
      "label_de": "Veranstaltungsdetails",
      "label_en": "Event details",
      "url": "https://example.org/event",
      "primary": true
    }
  ],
  "audio_url": null
}
```

Supported optional fields include:

- `end` or `duration_hours`
- `slug` for a stable custom URL component
- `label_de` / `label_en`
- `location`, or `location_de` / `location_en`
- `details_de` / `details_en`
- `image` or `image_url`
- `lineup`
- `tracklist`
- `links`

Generated routes use:

```text
/sendungen/YYYY-MM-DD-title/
/termine/YYYY-MM-DD-title/
```

On the homepage the same URL opens an accessible modal/drawer through progressive enhancement. Opening it in a new tab, refreshing it, or disabling JavaScript serves the standalone static page.

A standard `.ics` calendar file is generated for each upcoming entry. Broadcast files include the Radio Blau stream URL as a comment.

## Add details to archived broadcasts

The SoundCloud cache supplies the base archive. To add a tracklist, image, translated description or longer text, add a matching past object to `content/episodes.json` with the exact `audio_url`. The build merges those local additions into the cached archive without overwriting them during the next refresh.

## Archive refresh

The scheduled workflow `.github/workflows/refresh-archive.yml`:

1. runs daily or manually,
2. reads the SoundCloud playlist through `yt-dlp`,
3. updates `content/archive-cache.json`,
4. commits only when the cache changed,
5. explicitly starts the separate Pages deployment workflow after a changed cache.

Ordinary content or design deployments do not depend on SoundCloud being available.

## Build and preview locally

Install the normal build requirements once:

```cmd
cd /d M:\dev\sofea-github-pages
py -m pip install -r requirements.txt
```

`requirements.txt` installs `tzdata` only on Windows, where Python normally has no system IANA timezone database.

Build and preview:

```cmd
set SITE_URL=http://localhost:8000
py scripts\validate_site.py --source
py scripts\build.py
py scripts\validate_site.py --public
py -m http.server 8000 --directory public
```

Open `http://localhost:8000` and stop the server with `Ctrl+C`.

Updating the SoundCloud archive locally is optional:

```cmd
py -m pip install -r requirements-archive.txt
py scripts\update_archive.py --strict
```

## Deployment and pull requests

- `.github/workflows/pages.yml` validates, builds and deploys pushes to `main`.
- `.github/workflows/quality.yml` validates pull requests without deploying them.
- `.github/workflows/refresh-archive.yml` is the only workflow with repository write permission.
- `.github/dependabot.yml` checks Python and GitHub Actions dependencies monthly.
